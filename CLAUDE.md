## Project Overview

This is a monorepo containing two independent applications:
1. **Frontend**: Next.js 14 application with TypeScript and Tailwind CSS (uses `/app` directory)
2. **Backend**: Spring Boot application with Gradle (uses `/src` directory following Maven conventions)

The projects are merged in a single repository but can be developed independently. Git branches follow the pattern `feature/[project-name]-[description]`.

## Frontend (Next.js)

### Quick Commands
- `npm run dev` - Start development server (http://localhost:3000)
- `npm run build` - Production build
- `npm run start` - Run production build
- `npm run lint` - Run ESLint checks
- `npm run format` - Format code with Prettier (uses Tailwind plugin for class sorting)

### Architecture
- **App Router**: Uses Next.js 13+ app directory structure (`/app`)
- **TypeScript**: Strict mode enabled, configured with path alias `@/*` pointing to project root
- **Styling**: Tailwind CSS v4.1+ with PostCSS pipeline
- **Type Definitions**: Auto-generated by Next.js in `.next/types/`

### Key Configuration Files
- `tsconfig.json`: Strict TypeScript, ES2020 target, import extensions allowed
- `next.config.js`: React strict mode enabled
- `tailwind.config.ts`: Tailwind configuration
- `.eslintrc.json`: Extends Next.js core-web-vitals rules
- `eslint.config.js`: Uses eslint-plugin-react, React import not required in scope

### Important Patterns
- Metadata defined in layout components using `export const metadata`
- All TypeScript files must be valid (strict mode enforced)
- React Server Components are the default in app directory
- Tailwind classes automatically sorted by prettier-plugin-tailwindcss

## Backend (Spring Boot)

### Quick Commands
- `./gradlew bootRun` - Run development server (http://localhost:8080)
- `./gradlew build` - Build project (outputs to `build/`)
- `./gradlew test` - Run tests
- `./gradlew clean` - Clean build artifacts

### Architecture
- **Framework**: Spring Boot 2.7.14
- **Build Tool**: Gradle
- **Java Version**: Java 21
- **Testing**: JUnit Platform

### Dependencies
- **Web**: `spring-boot-starter-web` (REST APIs)
- **Data**: `spring-boot-starter-data-jpa` (Database ORM)
- **Database**: H2 (in-memory, runtime-only)
- **Testing**: `spring-boot-starter-test` (JUnit, Mockito, etc.)

### Project Structure
- `src/main/java/com/example/` - Application code
  - `DemoApplication.java` - Entry point
  - `controller/` - REST controllers
  - Other domain packages follow Maven conventions
- `src/test/java/com/example/` - Test code (follows test naming: `*Tests.java`)

### Important Patterns
- Main class annotated with `@SpringBootApplication`
- Controllers use Spring MVC annotations
- H2 database is in-memory, suitable for development/testing
- Tests use Spring Boot Test framework

## Frontend-Backend Integration

### API Communication
- Backend runs on `http://localhost:8080`
- Frontend runs on `http://localhost:3000`
- CORS configuration may be needed if making cross-origin requests

### Development Workflow
- Start backend first: `./gradlew bootRun` in project root
- Then start frontend: `npm run dev` in project root
- Both services run independently; coordinate integration points through environment variables if needed

## Development Tips

### Frontend-Specific
- Path alias `@/*` resolves to project root for cleaner imports
- Tailwind classes are automatically sorted; run formatter regularly
- TypeScript strict mode catches many issues at compile time
- `.next/` directory contains auto-generated types; don't edit manually

### Backend-Specific
- Gradle wrapper (`./gradlew`) ensures consistent Gradle version across environments
- H2 console available during development for database inspection
- Spring Boot auto-restarts on file changes during `bootRun`
- Use `@Test` annotation from JUnit for test methods

## Common Issues

**Frontend build fails with type errors**: Ensure `npm install` has been run; check tsconfig.json strict settings

**Backend tests fail to run**: Use `./gradlew test --info` for detailed output; verify Java 21 is available

**CORS issues between frontend and backend**: Configure Spring Security or use `@CrossOrigin` annotation on controllers

**Node modules or build artifacts cluttering workspace**: Add to .gitignore; run `npm clean-install` for frontend or `./gradlew clean` for backend
